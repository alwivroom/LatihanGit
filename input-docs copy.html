Slot guidelines

• Left content — use for prefix icons, country codes, or currency symbols that contextualise the expected input.

• Right content — use for suffix labels, unit indicators, or secondary actions (e.g. clear, toggle visibility).

• Helper text — always show when extra guidance or error feedback is needed. Pair with the Error state for validation messages.

• Both Left and Right content can be active simultaneously when each communicates a distinct piece of information.

Usage Guidelines

Guidance on when and how to use the Input component correctly.

✓ Do
Match size to context
Use LG for prominent hero forms, MD for standard forms, SM/XS for dense or inline UIs.
✓ Do
Always show a visible label
Users need to know what to enter at all times — label text must always be visible above or inside the field.
✓ Do
Pair Error with Helper text
When validation fails, set the Error state and include a Helper message that tells the user exactly how to fix the problem.
✓ Do
Use slots for contextual signals
Left/Right content slots communicate domain context (e.g. "+61" prefix, "AU" suffix) that the user needs before typing.
✗ Don't
Mix sizes in the same form
Inconsistent sizes disrupt visual rhythm and make forms feel unpolished. Pick one size per form and stick to it.
✗ Don't
Rely on placeholder text as label
Placeholder disappears when the user starts typing — this leaves them with no label to reference mid-input.
✗ Don't
Show errors without explanation
"Invalid input" alone is not actionable. Always tell the user what went wrong and how to correct it.
✗ Don't
Overload both slots with unrelated content
Filling both Left and Right with decorative or redundant content clutters the input and reduces scannability.
